# LightRAG 图增强检索

## 简介
LightRAG（香港大学）是一个**把图结构引入检索**的 RAG 框架：先用 LLM 从文档中抽取实体与关系，构建知识图谱，再把"向量检索"和"图检索"结合成双层检索。它的定位是 GraphRAG 的**轻量替代**——保留图增强的核心收益，去掉昂贵的社区发现与层级摘要。

## 核心机制

**1. 抽取建图**
文档切块 → LLM 抽取实体、关系、关键词 → 写入图库（支持 Neo4j），同时把实体与关系的描述也做向量化，存入向量库。

**2. 双层检索（Dual-level）**
| 层级 | 检索什么 | 擅长回答 |
|---|---|---|
| 低层（Low-level） | 具体实体及其属性、邻居 | "X 是什么、X 和 Y 什么关系" |
| 高层（High-level） | 主题、概念、关系模式 | "这类问题整体上有哪些共性" |

两层结果与原始文本块一起送入生成阶段，形成**向量 + 图 + 原文**的三重证据。

**3. 增量更新**
新文档进来只需抽取新增实体与关系并合并进图，**不需要全量重建**——这是相对 GraphRAG 的关键工程优势。

## 与 GraphRAG 的对比

| 维度 | GraphRAG（微软） | LightRAG |
|---|---|---|
| 图结构 | 社区检测 + 层级摘要 | 扁平图，无社区层级 |
| 索引成本 | 高（LLM 调用量大） | 显著低（第三方评测称低约两个数量级，具体随语料变化） |
| 索引耗时 | 长 | 短 |
| 全局性问题 | 强（社区摘要支撑） | 较弱（无层级摘要） |
| 增量更新 | 复杂 | 简单 |
| 多跳推理 | 强 | 中 |

## 适用边界
**适合**
- 语料中等规模、需要多跳/关系型问答（如设备—故障—处置方案的关联）；
- 数据频繁更新，无法接受全量重建；
- 预算有限但想获得图增强收益。

**不适合**
- 需要"总结全部文档的主要主题"这类全局归纳 → GraphRAG 更合适；
- 已有大规模历史图数据（LightRAG 只能用自己生成的图，无法直接复用外部图谱）；
- 语料本身没有明显实体关系结构（纯叙述性文本），建图收益有限。

## 关键风险
- **抽取质量决定一切**：LLM 抽取错一个实体名，图里就多一个孤立节点，检索时被当成噪声；
- **实体消歧缺失**：同一设备的不同叫法会变成多个节点，需要额外的规范化步骤；
- **图规模膨胀**：实体数量随语料线性增长，最终又回到"检索精度"问题。

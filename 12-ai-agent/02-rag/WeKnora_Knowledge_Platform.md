# WeKnora 知识平台

## 简介
WeKnora（维娜拉）是腾讯开源的企业级知识库平台（MIT 协议），定位一句话概括：**把原始文档变成三样东西——可查询的 RAG、自主推理的 Agent、自维护的 Wiki**。三种能力共享同一批知识库，是它与其他 RAG 产品最大的不同。

技术栈：Go 后端 + Vue 3 前端 + Python 文档解析服务（docreader）；支持 Docker Compose、Helm、Lite 单二进制与桌面版部署。

## 三种模式

| 模式 | 做什么 | 对应知识工作的层次 |
|---|---|---|
| **RAG 快速问答** | 检索知识库 → 生成回答 → 标注引用来源 | 查（quick lookup） |
| **ReAct 自主 Agent** | 规划多步任务，检索 + 调 MCP 工具 + 沙箱执行 + 网页搜索 | 做（complex task） |
| **Wiki 自维护** | 从文档抽取人物/产品/概念，生成互相链接的结构化页面 + 知识图谱 | 沉淀（knowledge asset） |

## Wiki 模式为什么特别
市面上 RAG 产品普遍具备前两种能力，**Wiki 模式是稀缺项**：

- **不是"等你来查"，而是"主动整理"**：文档入库后自动蒸馏成主题页面，带来源引用；
- **可持续维护**：新文档进来会增量更新相关页面，而非只堆原始文件；
- **可编辑、可回滚**：页面支持版本 diff 与一键回滚，把知识库变成可运营的资产；
- **带知识图谱**：页面之间的关联可视化，支撑"顺藤摸瓜"式探索。

> 本质上它把"检索"从**一次性动作**变成了**持续积累的结构**——这一点和 Obsidian 的双链笔记思路同源：知识的价值在于被组织，而不在于被囤积。

## 检索与工程能力
- **混合检索**：向量 + BM25 + RRF 融合 + Rerank 重排（可选 GraphRAG，图存 Neo4j）；
- **文档理解**：版式分析、扫描件 OCR、表格抽取、图片多模态描述、音频转写；
- **数据源**：飞书 / Notion / Confluence / 语雀 / 钉钉 / GitLab / RSS 自动同步；
- **模型**：内置 29 家厂商，LLM / Embedding / Rerank / VLM / ASR 分类管理，可接 Ollama 本地模型；
- **多租户**：工作空间 RBAC 四级角色、审计日志、AES-256 凭据加密；
- **可观测**：Langfuse 全链路追踪（Agent 步骤、token 用量、流水线）。

## 边界与注意点
1. **部署门槛不低**：完整功能（含 Langfuse、Milvus 等可选组件）内存需求可能超过 16 GB，资源受限环境需要裁剪服务；
2. **文档解析质量决定上限**：复杂 PDF 与扫描件的 OCR 准确率不稳定，必要时换解析引擎（MinerU / OpenDataLoader）；
3. **Wiki 更新有延迟**：大知识库下依赖文档解析队列，不是实时同步；
4. **治理成本**：功能面很宽，团队若无人维护数据源与权限，容易退化成"又一个网盘"。

## 与 LightRAG 的定位差异
| | LightRAG | WeKnora |
|---|---|---|
| 定位 | 检索算法框架（库） | 完整知识平台（产品） |
| 图能力 | 核心机制，双层检索 | 可选增强（GraphRAG + Neo4j） |
| 上手成本 | 低（Python 库） | 中（需部署整套服务） |
| 适用 | 嵌入自有系统 | 团队/企业直接使用 |

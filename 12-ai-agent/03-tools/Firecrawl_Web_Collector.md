# Firecrawl 网页采集

## 简介
Firecrawl 是一个**面向大模型的网页采集器**：把网页抓取下来、清洗掉导航/广告/脚本，输出干净的结构化内容（Markdown / JSON），直接可用于 RAG 入库或作为模型上下文。它解决的不是"能不能抓到"，而是"抓到的内容能不能直接喂给模型"。

## 核心能力
| 能力 | 说明 |
|---|---|
| 单页抓取（scrape） | URL → 干净 Markdown / HTML / 结构化 JSON |
| 站点爬取（crawl） | 按规则递归遍历站点，返回全部页面 |
| 站点地图（map） | 快速枚举站点所有 URL，用于规划抓取范围 |
| 结构化抽取（extract） | 按给定 schema 从页面提取字段（适合批量整理规格参数） |
| 变更监控 | 定期抓取并比对差异 |

## 自托管成本
- 官方给出的最低配置约为 **4 GB 内存 + 10 GB 存储**（Docker Compose 部署）；
- 若开启浏览器渲染、并发抓取等能力，资源需求会明显上升；
- 云服务版本按调用量计费，省去运维。

## 引入判断：什么情况下值得
| 场景 | 建议 |
|---|---|
| 偶尔查几个网页 | 直接用云 API，不自建 |
| 需要把某个站点整体入库 | 云 API 或临时自建，用完即弃 |
| 长期、高频、数据敏感（不出内网） | 才考虑常驻自托管 |

> **判断标准**：这个能力是否**阻塞主流程**？如果只是"偶尔用得上"，引入一套常驻基础设施的投入产出比不成立。**先按需调用验证价值，成为刚需再自建。**

## 替代方案
| 工具 | 特点 | 何时选它 |
|---|---|---|
| Firecrawl | 输出对 LLM 友好，功能全 | 需要批量、结构化、可维护 |
| Jina Reader | 单页转 Markdown，轻量 | 只需要"读一个网页" |
| Playwright / Puppeteer | 完全可控，需自己写清洗逻辑 | 有复杂交互（登录、翻页、点击） |
| 站点官方 API / RSS | 最稳定、最合规 | 对方提供时必须优先用 |

## 合规注意
- 遵守目标站点的 `robots.txt` 与服务条款；
- 抓取频率需限流，避免对对方服务造成压力；
- 涉及个人信息或受版权保护内容时，先确认授权边界。

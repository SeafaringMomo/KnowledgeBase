# 编码器—解码器架构

## 简介
编码器（Encoder）负责**理解**：把原始输入转换成一组稠密表示；解码器（Decoder）负责**生成**：从这些表示出发，逐步产出目标输出。二者组合即 seq2seq（序列到序列）架构，是机器翻译、摘要、语音识别的经典骨架。

> 一句话区分：**编码器把"世界"压缩成表示，解码器把表示展开成"答案"。**

## 两种组件的职责

| | 编码器 | 解码器 |
|---|---|---|
| 输入 | 完整源序列 | 已生成的部分 + 编码器输出 |
| 输出 | 每个位置的上下文表示 | 下一个 token 的概率分布 |
| 是否可见未来 | 可见（双向） | 不可见（因果掩码） |
| 目标 | 理解输入 | 生成输出 |

## 三种形态（按使用哪一半划分）

| 形态 | 代表模型 | 擅长 | 典型任务 |
|---|---|---|---|
| **Encoder-only** | BERT、RoBERTa | 理解：分类、抽取、向量化 | 情感分析、NER、检索 embedding |
| **Decoder-only** | GPT 系列、LLaMA、DeepSeek | 生成：续写、对话、推理 | 文本生成、对话、代码 |
| **Encoder-Decoder** | T5、BART、原始 Transformer | 输入到输出的转换 | 翻译、摘要、语音转写 |

**选型判据**：
- 输出是**标签/向量**（长度固定）→ encoder-only；
- 输出是**另一段文本**（长度不定、需自回归）→ decoder-only 或 encoder-decoder；
- 输入很长、输出较短且强依赖全文（摘要、翻译）→ encoder-decoder 仍有优势；
- 输入输出同质、需要统一建模（对话、通用助手）→ decoder-only 是当前主流选择。

## 历史演进：信息瓶颈与注意力的引入

**第一代 seq2seq（2014，RNN）**
```
源句 → RNN 编码器 → 单个固定长度向量 c → RNN 解码器 → 目标句
```
**致命缺陷**：整句信息被压进一个固定维度向量，句子越长丢得越多——这就是**信息瓶颈**。

**第二代：加注意力（Bahdanau, 2015）**
解码器每一步不再只看一个 c，而是"回头查"编码器的**所有隐状态**并加权求和。瓶颈被打开，长句翻译质量显著提升。

**第三代：Transformer（2017）**
把"回头查"这件事做成自注意力，彻底去掉循环结构，实现并行训练。Transformer 本质上是**编码器—解码器架构 + 纯注意力**的实现（详见 [Transformer 架构](Transformer_Architecture.md)）。

## 场景 / 优势 / 局限

**优势**
- 职责分离：理解与生成为不同目标优化，各自可以更深；
- 适合"输入信息量大、输出结构化"的任务（文档→摘要、语音→文本）；
- 编码器可单独复用（做检索、分类、聚类）。

**局限**
- **结构更复杂**：两套参数、两种注意力（自注意力 + 交叉注意力），训练与推理成本更高；
- **解码器仍需自回归**：生成阶段逐 token 串行，延迟居高不下；
- **对齐问题**：长文档编码后，解码器未必能定位到正确片段，需要额外检索或指针机制。

## 实践建议
1. 做**检索/分类/去重**：直接用 encoder-only 模型的向量输出，别自己训；
2. 做**生成式任务**：默认选 decoder-only 的通用模型，微调成本最低；
3. 只有在**输入极长且输出强依赖全文**（如长文档摘要、结构化抽取）时，encoder-decoder 的结构优势才明显；
4. 无论哪种形态，**输入长度与位置编码的外推能力**都是长文本任务的第一道坎。

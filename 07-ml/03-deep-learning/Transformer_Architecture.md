# Transformer 架构

## 简介
Transformer 由 Google 在 2017 年的论文《Attention Is All You Need》提出，用于机器翻译。它**彻底去掉循环与卷积**，仅用注意力 + 前馈网络堆叠成编码器—解码器结构。

它是当代 AI 的地基：BERT、GPT、T5、LLaMA、DeepSeek 全部是它的变体。理解 Transformer，等于拿到了读懂所有大模型的钥匙。

## 整体结构

```
输入 → Embedding + 位置编码
        ↓
   ┌─ 编码器 × N ─┐         ┌─ 解码器 × N ─┐
   │ 多头自注意力  │         │ 掩码自注意力  │
   │ 前馈网络      │  ─────▶ │ 交叉注意力    │
   └──────────────┘         │ 前馈网络      │
                            └──────────────┘
                                  ↓
                            线性层 + Softmax → 下一个词概率
```

原论文 base 配置：`N=6` 层编码器 + `6` 层解码器，`d_model=512`，`8` 个注意力头，`d_ff=2048`，约 **6500 万参数**。

## 各组件职责

| 组件 | 作用 | 关键细节 |
|---|---|---|
| 输入嵌入 | token → 向量 | 与输出层共享权重可减少参数 |
| 位置编码 | 注入顺序信息 | 正弦/余弦；现代模型改用 RoPE |
| 多头自注意力 | 让每个位置汇聚全序列信息 | 编码器双向，解码器加因果掩码 |
| 交叉注意力 | 解码器查询编码器输出 | Q 来自解码器，K/V 来自编码器 |
| 前馈网络 FFN | 逐位置非线性变换 | 通常两层 MLP，中间维度 4×d_model |
| 残差连接 | 缓解深层梯度消失 | `LayerNorm(x + Sublayer(x))` |
| 层归一化 | 稳定训练 | 原论文 Post-LN，现代多用 Pre-LN 或 RMSNorm |

**为什么残差 + LayerNorm 是关键**：没有它们，6 层以上就很难训；有了它们，才能堆到几十上百层（GPT-3 有 96 层）。

## 为什么它能取代 RNN

| 维度 | RNN / LSTM | Transformer |
|---|---|---|
| 并行性 | 必须按时间步串行 | 全序列并行 |
| 长距离依赖 | 需经 N 步传递，易衰减 | 任意两位置一步可达 |
| 训练速度 | 慢（GPU 利用率低） | 快（矩阵乘法打满） |
| 长序列成本 | O(n) | **O(n²)** ← 代价在此 |

**本质交换**：用**平方级的计算复杂度**换取了**并行能力与长程建模能力**。在 GPU 时代这笔交易极其划算，直到上下文长度成为瓶颈。

## 三种衍生形态
| 形态 | 取用部分 | 代表 | 训练目标 |
|---|---|---|---|
| Encoder-only | 只用编码器 | BERT | 掩码语言模型（完形填空） |
| Decoder-only | 只用解码器 | GPT / LLaMA / DeepSeek | 下一 token 预测 |
| Encoder-Decoder | 完整结构 | T5 / BART | 序列到序列 |

**为什么 decoder-only 成为主流**：训练目标统一（预测下一个词）、推理接口统一（生成）、缩放行为可预测，且一个模型能覆盖几乎所有任务。代价是双向理解能力弱于 encoder-only（做检索 embedding 时仍需专门模型）。

## 现代改进（相对 2017 原版）

| 方向 | 改进 | 解决的问题 |
|---|---|---|
| 归一化 | Pre-LN、RMSNorm | 深层训练稳定性、推理效率 |
| 位置编码 | RoPE / ALiBi | 长度外推 |
| 注意力效率 | MQA / GQA（共享 K/V 头） | KV cache 显存爆炸 |
| 长序列 | 稀疏注意力、FlashAttention、线性/混合注意力 | O(n²) 的算力与显存墙 |
| 容量扩展 | MoE（混合专家）：总参数大、激活参数小 | 用固定计算量换更大知识容量 |
| 激活函数 | SwiGLU 替代 ReLU | 同等算力下效果更好 |

## 场景 / 优势 / 局限

**优势**
- 通用性极强：文本、代码、音频、图像（ViT）、多模态都能用同一套骨架；
- 可扩展：缩放定律成立，加大参数与数据能可预测地降低损失；
- 生态成熟：框架、算子、推理引擎全部围绕它优化。

**局限**
- **O(n²) 复杂度**：上下文长度是硬约束，长文档处理必须靠检索或分块；
- **位置外推差**：训练长度之外的泛化需要专门技术；
- **无内置记忆**：每次推理从零开始，跨会话记忆必须外挂；
- **数据饥渴**：效果高度依赖训练数据的规模与质量，小数据场景不如传统模型。

## 实践建议
1. 做**应用开发**时不必自己训 Transformer，直接用开源权重 + 微调/LoRA；
2. 选模型时优先看四个指标：**上下文长度、激活参数量（决定推理成本）、是否 MoE、KV cache 优化方式**；
3. 做**长文档任务**先算一笔账：直接把 100K token 塞进去 vs 检索后塞 4K，成本可能差 20 倍以上；
4. 若要做**领域模型**，优先考虑 RAG 而非微调——知识更新成本差一个数量级。

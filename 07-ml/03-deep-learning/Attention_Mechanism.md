# 注意力机制（Attention）

## 简介
注意力机制回答一个朴素的问题：**在处理当前位置时，应该看输入里的哪些位置、各看多少？** 它把"看哪里"变成一个可微的加权求和，从而能端到端训练。

一句话类比：**它是模型内部的一次软检索**——用查询向量去和所有候选键比对，按匹配度加权取回对应的值。

## 核心机制

**Q / K / V 三件套**

| 符号 | 含义 | 类比 |
|---|---|---|
| Q（Query） | 当前位置想找什么 | 检索词 |
| K（Key） | 每个位置"能被什么找到" | 文档标题/标签 |
| V（Value） | 每个位置实际提供的内容 | 文档正文 |

三者都由同一份输入经三个独立线性变换得到（在自注意力中）。

**缩放点积注意力**

$$
\text{Attention}(Q,K,V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V
$$

| 步骤 | 作用 |
|---|---|
| $QK^\top$ | 一次矩阵乘法算出所有位置两两的匹配分数（n×n 矩阵） |
| $/\sqrt{d_k}$ | 缩放。d_k 越大点积方差越大，softmax 会饱和成"硬"分布、梯度趋零 |
| softmax | 每行归一化成和为 1 的权重 |
| $\times V$ | 按权重对 value 加权求和 |

**为什么它是革命性的**：整个计算只有两次矩阵乘法和一次 softmax，**没有循环**。任意两个位置之间的依赖路径长度为 1（RNN 需要 N 步），且所有位置可同时计算——这是 GPU 利用率提升一个数量级的根本原因。

## 多头注意力（Multi-head）

不是做一个注意力，而是并行做 h 个，各自用独立的投影矩阵，最后拼接再线性变换。

以原论文 base 配置为例：`d_model = 512`，`h = 8`，每个头 `d_k = d_v = 64`。**总计算量与单个 512 维头相当**，但模型可以同时学习多套"匹配标准"（有的头关注相邻位置、有的关注句法依存、有的关注指代）。

## 三种注意力形态

| 形态 | Q 来自 | K/V 来自 | 用在哪 |
|---|---|---|---|
| 自注意力（Self-attention） | 当前序列 | 同一序列 | 编码器、解码器内部 |
| 交叉注意力（Cross-attention） | 解码器 | 编码器输出 | encoder-decoder 连接处、多模态对齐 |
| 掩码自注意力（Masked） | 当前序列 | 同一序列（只能看过去） | 解码器的因果生成 |

**因果掩码**：把未来位置的分数置为 $-\infty$，softmax 后权重为 0，保证"预测第 t 个 token 时看不到第 t+1 个"。没有它，训练时模型会直接抄答案。

## 位置信息：注意力的盲区
纯自注意力对输入顺序是**置换等变**的——打乱词序，输出只是跟着重排。所以必须额外注入位置信息：

| 方案 | 说明 | 现状 |
|---|---|---|
| 正弦位置编码 | 原论文方案，固定频率的 sin/cos | 已基本被取代 |
| 可学习位置嵌入 | 每个位置一个可训练向量 | BERT 时代常用，外推差 |
| **RoPE（旋转位置编码）** | 把位置编码成向量的旋转角度 | 当前主流（LLaMA、Qwen、DeepSeek 等） |
| ALiBi | 用距离线性偏置注意力分数 | 部分长文本模型采用 |

RoPE 的优势在于**相对位置信息天然编码在点积中**，且可通过调整旋转基数做一定程度的外推。

## 场景 / 优势 / 局限

**优势**
- 长距离依赖直接建模（路径长度 O(1)）；
- 完全并行，训练效率高；
- 权重可视化，可解释"模型在看哪里"。

**局限（必须知道的边界）**
- **复杂度 O(n²d)**：序列长度翻倍，计算与显存翻四倍。这是长上下文的第一道物理墙，也是 KV cache 显存压力的来源；
- **无状态**：每次推理都要重算全部历史（除非用 KV cache）；
- **位置外推脆弱**：训练长度 4K，直接推理 128K 通常崩，需要 RoPE 缩放、插值或长上下文微调；
- **注意力不等于因果解释**：权重高只说明"信息流大"，不证明模型"依据"了它。

## 实践建议
1. 长上下文场景优先看**是否用了 GQA/MQA**（减少 KV cache 显存）与**RoPE 外推方案**；
2. 做可视化排查时，注意区分「attention weight」与「实际贡献」，可用 attention rollout / 梯度归因交叉验证；
3. 需要极长序列（>100K）时，考虑线性注意力、稀疏注意力或混合架构，但**先测质量损失**——省显存不等于保效果。

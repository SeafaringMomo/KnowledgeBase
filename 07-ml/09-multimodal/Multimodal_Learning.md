# 多模态学习

## 简介
多模态学习要让模型同时处理两种以上模态（图文、音视频、传感器）。核心难题不是"多接一个编码器"，而是**对齐**：如何把"一只猫的图片"和"一只猫的文字"映射到同一个语义空间里。

## 一、三种融合层次

| 层次 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **早期融合** | 原始特征直接拼接后输入 | 实现简单 | 模态异质性强，效果差 |
| **晚期融合** | 各模态独立编码，结果加权/投票 | 模块解耦、易扩展 | 丢失跨模态交互 |
| **交叉注意力融合** | 一侧作 Query 去查另一侧 | 细粒度对齐，效果最好 | 计算贵、结构复杂 |

**当前主流是"双塔 + 交叉注意力"的组合**：检索用双塔（可离线建索引），生成/推理用交叉注意力（精度优先）。

## 二、代表模型谱系

| 模型 | 类型 | 关键能力 |
|---|---|---|
| **CLIP** | 双塔对比学习 | 图文检索、零样本分类——用文本当分类器 |
| **BLIP / BLIP-2** | 视觉编码器 + Q-Former + LLM | 图文理解与生成桥接 |
| **Flamingo** | 视觉 token 注入 LLM + 门控交叉注意力 | 少样本多模态对话 |
| **GPT-4o / Gemini 类** | 原生多模态训练 | 端到端语音、图像、文本统一 |
| **Stable Diffusion 系** | 文本条件扩散 | 文生图，通过 cross-attention 注入文本 |

**CLIP 的思想价值**：它把"分类"变成了"检索"——不再需要为每个类别训练分类头，只要提供类别名称的文本描述，就能零样本分类。**这是"用语言当接口"的第一次大规模验证**。

## 三、对比学习：CLIP 的训练目标

一批 N 个图文对，编码后得到 N×N 的相似度矩阵：
- 对角线是正样本（匹配的图文）；
- 其余是负样本（批内其他图/文）。

$$
\mathcal{L} = -\frac{1}{2N}\sum_i\left[\log\frac{e^{s_{ii}/\tau}}{\sum_j e^{s_{ij}/\tau}} + \log\frac{e^{s_{ii}/\tau}}{\sum_j e^{s_{ji}/\tau}}\right]
$$

**关键点**：
- **温度 $\tau$** 控制分布的锐利度，是可学习参数；
- **批内负样本**是效果的关键——batch 越大，负样本越多，表征越好；
- 这带来一个工程约束：**CLIP 类模型的训练对 batch size 极度敏感**（动辄上万）。

## 四、典型应用

| 场景 | 方案 | 注意 |
|---|---|---|
| 图文检索 | CLIP 双塔 + 向量库 | 中文需中文 CLIP 或做迁移 |
| 图像描述 | BLIP-2 / 多模态 LLM | 会产生"看似合理但错误"的细节 |
| 文档理解（OCR + 理解） | 版面分析 + 多模态模型 | 表格与公式仍是弱项 |
| 视觉问答 | 多模态 LLM | 需评估"是否真的看图"，而非靠语言先验猜 |
| 文生图 | 扩散模型 + 文本编码器 | 提示词工程影响巨大 |

## 五、边界与代价

- **对齐质量取决于数据**：图文对噪声大（alt-text 常常与图无关），模型会学到错误关联；
- **组合泛化差**："红色立方体在蓝色球左边"这类关系推理，比单物体识别难得多；
- **模态缺失与不平衡**：训练时某模态缺失会导致模型偏向强势模态（通常是文本）；
- **评测困难**：多模态没有统一 benchmark，必须自建场景化评测集；
- **成本高**：视觉 token 数量可观，长视频输入会让上下文爆炸。

## 六、实践建议
1. **检索类任务用双塔，生成类任务用融合模型**，不要用一套架构打天下；
2. 中文图文场景**先测中文 CLIP**，直接用英文模型效果常掉一档；
3. 多模态模型的"看图能力"必须**用反事实样本验证**（换掉图片看答案是否变化），否则容易被语言先验骗过；
4. 视频场景先做**关键帧抽取**，再送多模态模型，直接送整段视频成本不可控。

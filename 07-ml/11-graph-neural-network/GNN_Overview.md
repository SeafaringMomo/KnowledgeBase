# 图神经网络概览

## 简介
图神经网络（GNN）处理**非欧几里得结构数据**：节点之间有任意连接关系（社交网络、分子结构、知识图谱、设备拓扑）。它的核心思想只有一句——**让每个节点不断聚合邻居的信息，从而把自己的表示更新得更"懂上下文"**。

对比：CNN 聚合固定邻域（3×3 窗口），GNN 聚合**任意拓扑上的邻居**。

## 一、消息传递范式（Message Passing）

几乎所有 GNN 都可以写成三步：

```
① 消息生成   m_ij = φ(h_i, h_j, e_ij)     邻居 j 发来的消息
② 聚合       a_i  = AGG({m_ij : j ∈ N(i)}) 求和/均值/最大
③ 更新       h_i' = ψ(h_i, a_i)            结合自身与聚合结果
```

堆叠 k 层，节点就能"看到" k 跳以内的邻居。**这就是 GNN 的全部骨架**，不同模型只是在 φ/AGG/ψ 上做文章。

## 二、代表模型对照

| 模型 | 聚合方式 | 关键贡献 | 局限 |
|---|---|---|---|
| **GCN** | 归一化加权平均 | 把谱图卷积简化为一阶近似，简单有效 | 权重与度绑定，难以区分邻居重要性 |
| **GraphSAGE** | 采样 + 聚合（mean/LSTM/pool） | **归纳式**：可对未见节点推理 | 采样带来方差 |
| **GAT** | 多头注意力加权 | 邻居权重可学习，可解释 | 计算与存储开销大 |
| **GIN** | sum 聚合 + MLP | 理论表达力最强（逼近 WL 测试） | 实践中未必最优 |

**直推式 vs 归纳式**：GCN 这类在固定图上训练、无法处理新节点；GraphSAGE/GAT 可以对新节点做前向计算——**工程落地优先选归纳式**。

## 三、必须知道的三个问题

**1. 过平滑（Over-smoothing）**
层数一多，所有节点表示趋同，分类性能反而下降。原因是反复平均把差异抹平了。
→ 对策：层数控制在 2–4 层、加残差、用 JKNet 保留中间层。

**2. 过挤压（Over-squashing）**
远距离信息要挤过有限的向量通道，长程依赖丢失。
→ 对策：图重连、加虚拟节点、改用图 Transformer。

**3. 异配图（Heterophily）**
"相连的节点应该相似"这个假设在欺诈检测、推荐等场景不成立（骗子更爱连正常人）。
→ 对策：改用能学负权重的模型，或显式建模关系类型。

## 四、应用场景

| 场景 | 图怎么建 | 典型任务 |
|---|---|---|
| 知识图谱 | 实体=节点，关系=边 | 链接预测、实体对齐 |
| 推荐系统 | 用户—物品二部图 | 召回、CTR 预估 |
| 分子/材料 | 原子=节点，键=边 | 性质预测、药物筛选 |
| 工业系统 | 设备=节点，管线=边 | 故障传播分析、根因定位 |
| 风控 | 账户—设备—IP 异构图 | 团伙欺诈识别 |

**工业场景的独特价值**：设备拓扑天然是图，故障会沿管线传播。**用 GNN 做根因定位，比逐个设备独立建模更符合物理现实。**

## 五、边界与代价

- **规模是硬约束**：百万级节点的全图训练显存吃不下，需要邻居采样（GraphSAGE）或子图训练；
- **依赖图质量**：边构建错了，GNN 只是把错误放大；**图构建往往比模型选型更决定成败**；
- **动态图难处理**：关系随时间变化时需要时序 GNN 或快照重训；
- **不一定打得过简单基线**：很多任务上，把邻居特征做简单聚合（甚至只用节点自身特征 + 图统计量）就能接近 GNN 效果——**上线前必须做这个 baseline**；
- **可解释性有限**：注意力权重不等于因果贡献。

## 六、实践建议
1. **先跑通"无图"基线**（仅节点特征 + 树模型），确认图结构确实带来增益；
2. 图构建优先于模型选型：明确"边代表什么语义"，比换 GCN→GAT 更重要；
3. 从 2 层 GCN/GraphSAGE 起步，别一上来堆深；
4. 大图必须做采样，且**训练与推理的采样策略要一致**；
5. 与知识图谱结合时，注意实体消歧——见 [Ontology 设计](../../12-ai-agent/02-rag/Ontology_Design.md)。

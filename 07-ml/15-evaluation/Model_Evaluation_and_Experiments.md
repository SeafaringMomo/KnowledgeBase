# 模型评估与实验设计

## 简介
**不会评估，就不会优化。** 这一章解决三个问题：怎么划分数据才不骗自己、怎么设计实验才能得出结论、怎么解释模型为什么这么判。

> 一条铁律：**没有评估集的调优，等于闭着眼睛改代码。** 你觉得变好了，可能只是记住了测试集。

## 一、数据划分

| 策略 | 做法 | 适用 | 陷阱 |
|---|---|---|---|
| Hold-Out | 按比例切 train/val/test | 数据量大 | 小数据方差大 |
| **K-Fold** | 切 K 份轮流验证 | 中小数据 | 必须分层（stratified） |
| 分层 K-Fold | 保持各类比例 | 类别不均衡 | — |
| 时间序列划分 | 按时间前推 | 时序数据 | **绝不能随机打乱** |
| 分组划分 | 按用户/设备分组 | 存在组内相关性 | 防止同组跨集泄漏 |

**三条不可违反的规则**：
1. **测试集只能用一次**（最终评估），不能拿来调参；
2. **时序数据必须按时间切**，随机划分 = 用未来预测过去；
3. **同一实体不能跨集**（同一患者的多次检查、同一设备的多个样本）。

## 二、指标选择

| 任务 | 首选指标 | 为什么 |
|---|---|---|
| 二分类（均衡） | Accuracy / F1 | 直观 |
| 二分类（不均衡） | **PR-AUC + F1** | Accuracy 会被多数类主导 |
| 排序/推荐 | **GAUC / NDCG** | 关注"用户内"排序 |
| 回归 | MAE / RMSE / R² | RMSE 惩罚大误差 |
| 检测 | mAP@IoU | 必须写清阈值 |
| 生成 | 人工 rubric / LLM-judge | 自动指标相关性有限 |

**指标必须与业务对齐**：风控关心"漏放率"（Recall），质检关心"漏检率"，搜索关心"首条命中"。**用错指标，模型会往错误方向优化。**

## 三、消融实验（Ablation）

目的：证明"每一个改动都是必要的"。

| 做法 | 说明 |
|---|---|
| 去掉某模块 | 看指标掉多少 |
| 替换为基线 | 与原方案对比 |
| 逐项累加 | 每加一项记录增量，识别"无效改动" |

**规范**：一次只改一个变量，其他条件（数据、种子、训练轮数）完全一致。**同时改三个东西的对比，结论无效。**

## 四、统计显著性

小数据集的指标波动可能比"改进"还大。

| 手段 | 用途 |
|---|---|
| 多种子重复（≥3 次） | 报告均值 ± 标准差 |
| 置信区间 / bootstrap | 判断差异是否稳健 |
| 配对检验（t-test / Wilcoxon） | 同一批数据上的 A/B 对比 |

**经验阈值**：如果改进幅度小于 2 倍标准差，**默认当作噪声**。

## 五、离线与线上的鸿沟

| 原因 | 表现 | 对策 |
|---|---|---|
| 数据分布不同 | 离线好、线上差 | 用线上回流数据做验证集 |
| 位置偏差 | 线上曝光位置影响点击 | 训练时纠偏 |
| 反馈闭环 | 只看到被推荐物品的反馈 | 探索机制 |
| 指标不一致 | 离线 AUC 涨，业务指标不动 | 建立线上代理指标 |
| **训练/推理不一致** | 特征计算逻辑不同 | 同一套特征代码 |

> **行业常态**：离线涨、线上不涨，甚至下跌。**只有 A/B 实验能证明价值。**

## 六、A/B 实验要点

1. **单一变量**：一次只改一个策略；
2. **样本量与时长**：先算最小样本量，别跑两天就下结论（周期效应）；
3. **护栏指标**：除了目标指标，还要监控延迟、错误率、投诉率；
4. **新奇效应**：新策略短期涨，长期回落，需观察 ≥2 周。

## 七、可解释性

| 方法 | 类型 | 适用 | 局限 |
|---|---|---|---|
| **SHAP** | 博弈论归因 | 表格数据、单样本解释 | 计算贵、特征相关时失真 |
| **LIME** | 局部线性近似 | 任意模型 | 不稳定，换种子结果会变 |
| 特征重要性 | 全局 | 树模型 | 共线特征下不可靠 |
| 注意力可视化 | 全局/局部 | Transformer | 权重高 ≠ 因果重要 |
| 反事实解释 | 局部 | 决策场景 | 需生成可行反例 |

**可解释性不是"画个热力图"**，而是能回答业务方的具体问题："为什么这个样本被拒绝？改成什么条件会被通过？"

## 八、边界与代价

- **评估成本常被低估**：建一个高质量评测集（200–500 条）需要领域专家数天时间，但它的价值高于任何模型调优；
- **自动指标会误导**：BLEU 高的摘要可能事实错误；AUC 高的模型可能校准很差；
- **可解释性方法本身不可靠**：不同方法给出的解释可能互相矛盾，只能作参考；
- **人类评估的主观性**：需要 rubric + 多人 + 一致性检验。

## 实践建议
1. **项目启动第一周就建评测集**，不要等到最后；
2. 报告指标必须写清：数据集、划分方式、随机种子、指标定义；
3. 任何改进都要问：**"这个提升能扛住换一个随机种子吗？"**
4. 上线用 **A/B + 护栏指标**，离线指标只作筛选；
5. 可解释性优先用 SHAP，且必须结合领域知识验证。

# 人工智能全景与学习路线

## 简介
这份笔记是 07-ml 分区的**总入口**：把散落在各章节的知识点按"发展脉络"和"能力分层"两个坐标组织起来，回答两个问题——**这些技术是怎么一步步演化出来的**，以及**我现在应该学哪一块**。

## 一、四条发展脉络

| 阶段 | 时间 | 核心方法 | 解决什么 | 天花板 |
|---|---|---|---|---|
| **符号主义** | 1950s–1980s | 专家系统、规则推理、知识图谱 | 把专家经验写成 if-else | 规则写不完、无法处理模糊输入 |
| **统计机器学习** | 1990s–2010s | 特征工程 + SVM/树模型/CRF | 从数据中自动估计参数 | 特征靠人设计，天花板=人的领域知识 |
| **深度学习** | 2012–2019 | 神经网络端到端学表示 | 自动学特征，无需人工设计 | 需要大量标注数据与算力 |
| **基础模型 / 生成式 AI** | 2020– | Transformer + 预训练 + 对齐 | 一个模型覆盖多任务，可生成 | 幻觉、成本、可控性 |

**这条线的主轴是"人退出的位置不断上移"**：先是人不写规则了（改喂数据），再是人不设计特征了（改搭网络），现在是人连任务都不逐个实现了（改用提示与上下文）。

## 二、能力分层地图

```
应用层    Agent / RAG / 工作流 / 产品化          → 12-ai-agent
─────────────────────────────────────────────
模型层    LLM / 多模态 / 生成模型                → 04-llm, 09-multimodal
─────────────────────────────────────────────
架构层    Transformer / CNN / RNN / GNN          → 03-deep-learning, 11-gnn
─────────────────────────────────────────────
方法层    监督 / 无监督 / 自监督 / 强化学习       → 01-models, 10-reinforcement-learning
─────────────────────────────────────────────
工程层    数据 / 特征 / 训练 / 推理 / 部署        → 13-data, 14-mlops
─────────────────────────────────────────────
基础层    线代 / 概率 / 优化 / 数值稳定           → 05-foundations
```

**读这张图的正确方式**：越往上越易变（应用层半年一换），越往下越稳定（线性代数几十年不变）。**投资回报率最高的是基础层与工程层**——它们不会过时，而且决定了你能不能把上层的东西真正跑起来。

## 四、学习路线（按目标分，不按难度分）

**路线 A · 应用落地（最快见效，2–3 个月）**
```
Python → 调用 LLM API → Prompt 设计 → RAG（检索+引用）→ Agent（工具调用）→ 评估与监控
```
这条路**不需要训练模型**，90% 的企业需求都能覆盖。重点在 [12-ai-agent](../12-ai-agent/00-Index.md)。

**路线 B · 算法工程（6–12 个月）**
```
数学基础 → 机器学习 → 深度学习 → Transformer → 训练调优 → 分布式与部署
```
适合要吃透原理、要改模型、要做领域微调的人。重点是 01–05 章。

**路线 C · 领域纵深（在 A 或 B 之上）**
```
选一个垂直方向（CV / NLP / 语音 / RL / 推荐）→ 精读 3–5 篇经典论文 → 复现 → 做一个小项目
```
**没有垂直纵深的人，在跨领域问题上会一直停在"会调包"的层次。**

## 五、常见误区

1. **按框架学，不按问题学**：学完 PyTorch 教程仍然不会做项目，因为缺的是"问题定义 → 数据 → 评估"这条链。
2. **跳过评估**：没有评估集的调优等于蒙眼开车。见 [模型评估与实验设计](15-evaluation/Model_Evaluation_and_Experiments.md)。
3. **迷信新模型**：多数业务问题的瓶颈在数据和流程，不在模型结构。
4. **只做上层**：只会调 API 的人，遇到"效果不好"时无法定位是检索、提示、还是模型能力问题。

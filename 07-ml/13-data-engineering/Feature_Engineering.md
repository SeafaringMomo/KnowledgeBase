# 特征工程

## 简介
特征工程是"把原始数据变成模型能有效利用的数值表示"。深度学习削弱了它的重要性，但没有消除它——**在表格数据上，特征质量仍然比模型结构更决定成败**。

> 一句经验：**表格数据先比特征，再比模型；深度学习先比数据，再比结构。**

## 一、预处理：四类基本操作

| 操作 | 做什么 | 什么时候用 | 陷阱 |
|---|---|---|---|
| **标准化**（Z-score） | $x' = (x-\mu)/\sigma$ | 特征量纲差异大、用梯度下降 | 树模型不需要 |
| **归一化**（Min-Max） | $x' = (x-\min)/(\max-\min)$ | 需要固定区间（如神经网络输出） | 对异常值极敏感 |
| **One-Hot** | 类别展开为 0/1 向量 | 类别数少（<50） | 高基数会维度爆炸 |
| **Embedding** | 类别映射为稠密向量 | 高基数类别（用户 ID、商品 ID） | 需足够数据才学得出来 |

**关键判断**：树模型（XGBoost/LightGBM）对单调变换不敏感，**标准化对它没有意义**；线性模型与神经网络则必须做。

## 二、特征构造：真正拉开差距的地方

| 类型 | 例子 | 适用 |
|---|---|---|
| **交叉特征** | 城市 × 品类、设备型号 × 工况 | 捕捉组合效应（FM/DeepFM 可自动学） |
| **统计特征** | 近 7 天均值、标准差、最大最小值 | 时序数据的核心 |
| **窗口特征** | 滚动 1h/24h/7d 聚合、差分、同比环比 | 工业与金融最常见 |
| **时间特征** | 小时、星期、是否节假日、距上次事件时长 | 强周期场景必须 |
| **比率/差值** | 转化率、温度差、负载率 | 比绝对值更有物理含义 |
| **文本统计** | 长度、关键词命中、TF-IDF | 轻量文本场景 |

**工业设备场景的经验**：**物理量之间的比值与差值，往往比原始量更有判别力**（如"温升/负荷"比"温度"更能反映异常）。

## 三、特征选择：三派方法

| 方法 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **Filter** | 用统计量打分（相关系数、卡方、互信息） | 快、与模型无关 | 忽略特征间交互 |
| **Wrapper** | 用模型效果做搜索（RFE、前向选择） | 直接优化目标 | 计算贵、易过拟合 |
| **Embedded** | 训练中自动选择（L1、树模型 importance） | 兼顾效率与效果 | 依赖模型 |

**注意**：树模型的 `feature_importance` 在**共线特征**下不可靠（重要性会被随机分摊），要用 SHAP 或分组打乱验证。

## 四、降维

| 方法 | 类型 | 适用 |
|---|---|---|
| PCA | 线性、无监督 | 特征高度相关、需要去冗余 |
| LDA | 线性、有监督 | 分类任务，需要类间可分 |
| t-SNE / UMAP | 非线性 | **只用于可视化**，不要喂给模型 |
| 自编码器 | 非线性 | 高维复杂数据（见 [自编码器](../03-deep-learning/Autoencoder.md)） |

## 五、特征泄漏：最隐蔽的致命错误

**定义**：训练时用到了预测时拿不到的信息。

| 泄漏类型 | 例子 | 后果 |
|---|---|---|
| 时间泄漏 | 用未来数据算滑动平均 | 离线 AUC 0.95，线上 0.6 |
| 目标泄漏 | 用"是否理赔"派生的字段预测"是否理赔" | 模型学到作弊特征 |
| 划分泄漏 | 同一用户/同一设备同时出现在训练与测试集 | 指标虚高 |
| 预处理泄漏 | 在全量数据上算标准化参数后再划分 | 轻微但真实存在 |

**检测手段**：某个特征的重要性异常高、离线指标好得不像话——**先怀疑泄漏，再庆祝**。

## 六、边界与代价

- **深度学习弱化了手工特征**，但没有消灭它：结构化表格上 GBDT + 好特征仍是最强基线；
- **特征越多不等于越好**：噪声特征会增加过拟合风险与推理成本；
- **维护成本被低估**：上线 200 个特征，任何一个上游变更都会静默破坏模型，必须做**特征监控**；
- **线上一致性**：训练用 Python 算的特征，线上要用 Java 重算一遍——**两套实现必然漂移**，这是生产事故的高发区。

## 实践建议
1. **先做 EDA + 单特征分析**，再谈建模；
2. 表格任务**基线固定为 LightGBM**，它能快速告诉你特征的实际上限；
3. 任何特征都要问一句：**"预测时刻，这个值真的能拿到吗？"**；
4. 训练与线上特征必须**同一套代码**（Feast 等特征平台的价值就在这）；
5. 特征数量控制在可维护范围内，宁少勿滥。

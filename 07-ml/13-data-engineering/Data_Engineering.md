# 数据工程与数据处理

## 简介
模型的上限由数据决定。数据工程要解决的不是"把数据喂进去"，而是**保证数据在采集、清洗、标注、存储、增强的每一环都不引入系统性偏差**。

> 行业共识：**80% 的模型效果问题最终归因到数据**。但多数团队把 80% 的时间花在调模型——这是最大的投入错配。

## 一、数据全生命周期

```
采集 → 清洗 → 标注 → 存储 → 版本管理 → 增强 → 训练/评估
```

## 二、采集：先想清楚"分布"

| 模态 | 关键要素 | 常见失误 |
|---|---|---|
| 图像 | 分辨率、光照、遮挡、角度、多样性 | 只用一种设备/一个车间采集 |
| 语音 | 对象、噪声、采样率、麦克风、口音、语速、标注规范 | 实验室安静环境，现场全废 |
| 文本 | 来源、时间跨度、领域覆盖、脱敏 | 训练数据含未来信息（时序泄漏） |
| 传感器 | 采样频率、量程、标定、时间同步 | 多设备时钟不同步 |

**第一原则：采集分布必须覆盖部署分布。** 训练集和线上数据的分布差异（域偏移）是模型上线后性能骤降的第一原因。

## 三、清洗：五项基本动作

| 动作 | 做法 | 注意 |
|---|---|---|
| 缺失值 | 删除 / 均值填充 / 模型插补 / 保留为特殊值 | **缺失本身可能是信号**（如"未检测"意味着设备离线） |
| 异常值 | 3σ、IQR、孤立森林 | 先判断是错误还是真实极端事件，别一律删掉 |
| 去重 | 精确哈希 + 近似去重（MinHash） | 重复样本会放大偏差 |
| 一致性 | 单位、编码、时间格式统一 | 工业数据的单位混乱极常见 |
| 噪声 | 滤波、平滑、人工抽检 | 过度平滑会抹掉真实特征 |

## 四、标注：成本与质量的核心战场

| 类型 | 标注形式 | 成本 | 质量控制 |
|---|---|---|---|
| 分类 | 类别标签 | 低 | 多人标注 + 一致性检验（Kappa） |
| 检测 | 边界框 | 中 | 交叉复核、难例复审 |
| 分割 | 像素级掩码 | 极高 | 抽样复核 + 预标注加速 |
| 序列标注 | 实体/词性 | 中 | 标注规范文档 + 定期校准 |
| 生成 | 参考答案/偏好对 | 高 | rubric 打分 + 双盲 |

**提高效率的三个手段**：
1. **预标注**：模型先跑一遍，人工只改错——通常能省 50–70% 时间；
2. **主动学习**：优先标注模型最不确定的样本；
3. **弱监督/半自动**：规则 + 模型生成候选，人工审核。

**标注规范必须写文档**：什么算"缺陷"、边界怎么框、模糊样本怎么判。规范不统一，标注质量再高也是噪声。

## 五、数据版本与可复现

| 实践 | 作用 |
|---|---|
| 数据集版本号（v1/v2 + 日期） | 实验可追溯 |
| 保存划分文件（train/val/test 索引） | 防止不同实验用了不同划分 |
| 记录预处理脚本 | 保证重跑一致 |
| **锁定测试集**，禁止用于调参 | 避免测试集污染 |

> **最常见的科研级错误**：反复用测试集调超参，最后报告的指标是"在测试集上过拟合的结果"。

## 六、数据增强

| 模态 | 方法 | 慎用场景 |
|---|---|---|
| 图像 | 翻转、旋转、裁剪、MixUp、CutMix、Mosaic、色彩抖动 | 工业缺陷不能随意翻转（破坏物理合理性） |
| 文本 | 同义词替换、回译、随机删除、掩码 | 法律/医疗文本，语义不能改 |
| 语音 | 加噪、变速、SpecAugment、混响 | 声纹识别不能做变速（改变身份特征） |
| 表格 | SMOTE 过采样、噪声注入 | 会破坏特征间相关性 |

**原则**：增强必须**保持标签语义不变**。凡是不确定是否保语义的增强，都不要用。

## 七、边界与代价

- **数据不是越多越好**：100 万条低质数据不如 1 万条高质量数据（尤其在微调场景）；
- **隐私与合规**：个人信息需脱敏，跨境传输有法律限制；
- **标注成本常被低估**：一个中等规模分割项目，标注费用可能超过算力费用；
- **数据债会复利**：脏数据在模型迭代中不断放大，越晚治理成本越高。

## 实践建议
1. **建一个"数据体检"清单**：缺失率、重复率、标签分布、时间跨度、域覆盖，每次训练前跑一遍；
2. **先做 1000 条高质量样本**跑通链路，再扩量——早期扩量只会放大错误；
3. 划分数据集时**按时间或按设备划分**，不要随机划分（否则信息泄漏）；
4. 用"模型预测错的样本"反推数据问题，比盲目加数据有效。

# 自然语言处理概览

## 简介
NLP 解决"让机器理解与生成人类语言"的问题。它的技术史可以浓缩成一句话：**从"人设计规则和特征"走到"模型自己学表示"**——分词与词向量是前深度学习时代的遗产，Transformer 之后一切都变成了"预训练 + 微调/提示"。

## 一、文本处理的四道工序

| 工序 | 做什么 | 现代做法 | 坑 |
|---|---|---|---|
| **分词 Tokenization** | 文本 → token 序列 | BPE / WordPiece / SentencePiece（子词） | 中文分词粒度、多语言混排、特殊字符 |
| **词表示 Embedding** | token → 稠密向量 | 可学习 embedding 或预训练向量 | 静态词向量无法区分多义词 |
| **上下文编码** | 融合上下文信息 | Transformer（自注意力） | 长文本的 O(n²) 成本 |
| **任务头** | 输出标签/文本 | 分类头、序列标注头、生成头 | 任务与预训练目标不匹配 |

**关于 BPE 的直觉**：它从字符开始，反复合并最高频的相邻 pair，最终词表里既有整词也有词根片段。好处是**未登录词可以被拆成已知子词**，坏处是同一个词可能被切成不同片段（影响计数与对齐）。

## 二、模型演进：三代范式

| 代际 | 代表 | 训练目标 | 擅长 |
|---|---|---|---|
| 统计/神经序列模型 | HMM、CRF、RNN、LSTM | 序列标注、语言模型 | 小数据、强约束任务 |
| **预训练 + 微调** | BERT、RoBERTa | 掩码语言模型（完形填空） | 理解类：分类、NER、抽取、检索 |
| **预训练 + 生成** | GPT、LLaMA、Qwen | 下一 token 预测 | 生成类：对话、写作、代码、推理 |

**BERT 与 GPT 的根本分歧**：BERT 能看双向上下文但不会生成；GPT 只能看左侧但能自回归生成。**当代主流选择 GPT 路线**，因为一个生成模型可以通过提示完成理解任务，反之不成立。

## 三、任务—模型匹配表

| 任务 | 推荐方案 | 备注 |
|---|---|---|
| 文本分类 | 微调 encoder 模型 或 LLM few-shot | 数据少时优先 LLM + 提示 |
| 命名实体识别 NER | 微调 encoder + CRF 头 | 需要精确边界时仍优于纯生成 |
| 信息抽取（结构化） | LLM + JSON schema 约束输出 | 注意校验与重试 |
| 摘要 | LLM 生成 + 事实一致性检查 | 长文需分块 + 层次化汇总 |
| 翻译 | 专用翻译模型 或 LLM | 术语一致性需要术语表注入 |
| 问答 | RAG（检索 + 生成） | 见 [RAG 基础链路](../../12-ai-agent/02-rag/RAG_Pipeline_Basics.md) |
| 语义检索 | 双塔 embedding 模型 | 需专门训练的检索模型，不是通用 LLM |

## 四、评估指标

| 任务 | 指标 | 说明 |
|---|---|---|
| 分类 | Accuracy / F1 / AUC | 类别不均衡看 F1 与 PR-AUC |
| 序列标注 | 实体级 F1（严格匹配） | token 级 F1 会虚高 |
| 生成 | BLEU / ROUGE / BERTScore | 与人类判断相关性有限，只作趋势参考 |
| 语言模型 | 困惑度 Perplexity | 越低越好，但**不能跨 tokenizer 比较** |
| 开放问答 | 人工评估 / LLM-as-judge | 需要固定评分 rubric |

> **中文场景的额外注意**：BLEU/ROUGE 基于分词，中文需先确定分词器；不同分词器结果不可比，**报告指标时必须写清分词方案**。

## 五、边界与代价

- **长文本仍是难点**：注意力 O(n²)，且"中间遗忘"（lost in the middle）现象普遍——关键信息放在长上下文中间时召回率显著下降；
- **领域术语**：通用模型对工业术语（设备型号、规程编号）理解差，需术语表或领域微调；
- **中文 token 效率低**：同样内容中文消耗的 token 常多于英文，直接影响成本；
- **幻觉**：生成式模型会编造不存在的引用和数字，事实型任务必须外挂检索与校验；
- **评估困难**：生成质量没有单一指标，必须建立自己的评测集。

## 实践建议
1. **先判断任务是"理解"还是"生成"**，再选模型路线，别一上来就用最大的模型；
2. 中文项目**优先选中文语料充分训练的模型**，并实测 token 效率；
3. 任何涉及数字、引用、合规表述的场景，**必须加规则校验或人工复核**；
4. 建一个 50–200 条的领域评测集，比反复换模型有用得多。

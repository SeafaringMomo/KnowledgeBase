# 训练与推理优化

## 简介
训练优化解决"**怎么在有限显存和时间里训完更大的模型**"；推理优化解决"**怎么让模型跑得更快更便宜**"。两者手段不同，但目标一致：**用更少的资源换同样的效果**。

## 一、训练循环的标准骨架

```
数据加载 → 前向传播 → 计算损失 → 反向传播 → 梯度裁剪 → 优化器更新 → 学习率调度 → 验证
```

**三个容易被忽略的点**：
1. **warmup + 余弦衰减**是默认配置，尤其大模型不加 warmup 容易发散；
2. **梯度累积**可以在小显存上模拟大 batch（累积 N 步再更新）；
3. **梯度检查点（activation checkpointing）**用计算换显存，能显著降低显存占用（代价慢 20–30%）。

## 二、分布式训练

| 方式 | 切分什么 | 适用 | 通信开销 |
|---|---|---|---|
| **数据并行 DP/DDP** | 切数据，每卡一份完整模型 | 模型能装进单卡 | 中（梯度 all-reduce） |
| **张量并行 TP** | 切单层内的矩阵 | 单层就装不下 | 高（每层都要通信） |
| **流水线并行 PP** | 切层，按 stage 分布 | 超深模型 | 中（气泡等待） |
| **ZeRO / FSDP** | 切优化器状态、梯度、参数 | 大模型首选 | 中高 |

**ZeRO 的三个阶段**（理解这个就理解了显存去哪了）：
- Stage 1：切分**优化器状态**（Adam 的 m/v，占大头）；
- Stage 2：再切分**梯度**；
- Stage 3：再切分**参数本身**（等价于 FSDP）。

**现实组合**：大模型训练通常是 **TP + PP + DP** 三维并行，或用 FSDP 简化。

## 三、混合精度

| 精度 | 位数 | 特点 |
|---|---|---|
| FP32 | 32 | 基准，显存与算力开销大 |
| FP16 | 16 | 快，但**动态范围小，容易溢出**（需 loss scaling） |
| **BF16** | 16 | 动态范围与 FP32 相同，**大模型默认选择** |
| FP8 | 8 | 新一代硬件支持，进一步提速 |

**AMP（自动混合精度）**：前向用半精度、累加与更新用 FP32，框架自动插入 cast。**用 AMP 而不是手动改 dtype。**

## 四、参数高效微调（PEFT）

| 方法 | 做法 | 显存 | 适用 |
|---|---|---|---|
| 全量微调 | 更新全部参数 | 极高 | 数据充足、要改能力 |
| **LoRA** | 冻结原权重，学习低秩增量 $W + BA$ | 低 | 默认选择 |
| **QLoRA** | 基座 4-bit 量化 + LoRA | 最低 | 单卡微调大模型 |
| Prefix/P-Tuning | 学习虚拟 token | 低 | 少样本 |

**LoRA 的关键参数**：秩 `r`（8–64）、`alpha`（通常 2r）、作用层（一般只加在 attention 的 q/v 上）。**r 不是越大越好**——过大会接近全量微调，失去效率优势。

## 五、推理优化

| 手段 | 原理 | 收益 |
|---|---|---|
| **KV Cache** | 缓存历史 key/value，避免重复计算 | 长文本生成必用；显存换速度 |
| **GQA / MQA** | 多查询共享 KV 头 | 大幅降低 KV cache 显存 |
| **连续批处理** | 动态拼批，不同长度请求共享 GPU | 吞吐提升数倍（vLLM 的核心） |
| **量化** | FP16→INT8/INT4（GPTQ/AWQ） | 显存降 2–4 倍，精度略降 |
| **蒸馏** | 大模型教小模型 | 小模型获得接近的能力 |
| **投机解码** | 小模型草稿 + 大模型校验 | 延迟降低 2–3 倍 |
| **FlashAttention** | 分块计算注意力，减少 HBM 读写 | 显存与速度双收益（不改变数学结果） |

## 六、超参数搜索

| 方法 | 特点 |
|---|---|
| Grid Search | 组合爆炸，只适合 ≤3 个超参 |
| Random Search | 同样预算下优于网格（高维空间更有效） |
| **Bayesian Optimization** | 用历史结果建模，样本效率最高 |
| 早停式（Hyperband/ASHA） | 提前杀掉差的 trial，省算力 |

**实践顺序**：先调学习率（影响最大），再调 batch size，最后调正则与结构。**不要同时调 10 个超参。**

## 七、边界与代价

- **分布式不是免费的**：通信开销可能吃掉并行收益，2 卡加速 1.9 倍已是好结果；
- **量化有精度损失**：INT4 在长上下文与代码任务上退化更明显，必须做任务级评测；
- **LoRA 不是万能**：需要注入新知识（而非调整行为）时，LoRA 效果有限；
- **FlashAttention 不改数学但改数值**：极端情况下结果有微小差异，不影响使用；
- **吞吐 ≠ 延迟**：批处理提升吞吐但增加单请求延迟，要按业务目标选。

## 实践建议
1. **先算显存账**：参数 + 梯度 + 优化器状态 + 激活值，四项相加；不够就上 ZeRO/检查点；
2. 单卡能放下就**别上分布式**，复杂度不值；
3. 微调默认 **LoRA + BF16**，显存不够再上 QLoRA；
4. LLM 服务用 **vLLM/SGLang**，别自己写 batching；
5. 优化前先 profile，**别凭感觉优化**——瓶颈常在数据加载而非计算。
